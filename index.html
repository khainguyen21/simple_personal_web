About.

I am a computer science student in San Jose. I like building things that solve a real problem for real people — not demos that sit in a folder.

Most of my time goes into two things. The first is code: I write full-stack apps with TypeScript, Next.js and PostgreSQL, and I write backend code in Java and Spring Boot. The second is teaching. I tutor Java at Evergreen Valley College, and explaining a hard idea to someone else is still the fastest way I have found to really learn it myself.

I also spend weekends at hackathons. My team won Best Physical AI Hack at the UC Berkeley AI Hackathon, and one of my school projects is now being used by the EVC Tutoring Center to run their schedule.

Next up: I transfer to a University of California in Fall 2027 and finish my bachelor's degree in 2029. Before that, I want an internship where I can ship real code with a real team.

Selected work.

Four projects. Hover or tap a row to open it.

  1. A scheduling app that replaced the tutoring center's messy spreadsheet. The manager at EVC is using it to run real schedules today.

    • Built the whole stack with Next.js 16, TypeScript, PostgreSQL and Prisma, with a live admin dashboard.
    • Used the Google Gemini API to read raw tutor emails and turn them into clean schedule data, so onboarding many tutors takes one paste and one click.
    Next.js 16TypeScriptPostgreSQLPrismaJWTGemini API
    Live site ↗ Code ↗

  2. Won Best Physical AI Hack. Our team of four turned a phone video of a boxing jab into a control policy for a 29-joint Unitree G1 humanoid robot.

    • Built the pipeline that goes from plain phone video to a trained robot policy (GVHMR → GMR → MLP policy training).
    • Recorded and sorted the boxing-jab clips that became the training data for the motion-capture step.
    • Worked in a 4-person team over one weekend against a hard hardware deadline.
    PythonMotion captureUnitree G1GVHMRPolicy training
    Devpost ↗

  3. An AI tutor for every kind of learner. People learn in different ways — by seeing, by hearing, by doing — so Learnr teaches the same idea through a shared whiteboard, diagrams, step-by-step notes, quizzes, animations, and spoken lectures.

    My part: the voice lecture

    • Built the lecture mode for students who learn best by listening. The AI teaches out loud, and the student can talk back and ask questions.
    • Used the VAPI API to make it a real two-way conversation, not a recording. Students can interrupt, mute the tutor, or end the lesson at any time.
    TypeScriptReactNode.jsVAPI API
    Devpost ↗

  4. A model that reads a job posting and guesses the career level it is written for. It gets it right about 77% of the time.

    • Trained a Random Forest classifier on job descriptions turned into numbers with TF-IDF.
    • Used SMOTE to fix the uneven classes, since some career levels had far fewer postings than others.
    • Cleaned the raw data and compared models in scikit-learn to pick the one that held up best.
    Pythonscikit-learnNumPyTF-IDFSMOTE
